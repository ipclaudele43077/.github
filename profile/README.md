<h2>一、清单的使用顺序</h2>
<p>清单的价值在于排除法。先看否决项，任何一条不满足就先解决它，因为优化项做得再好也补不回否决项。三条否决项都过了，再按加分项排序投入预算，避免一上来就买最贵的套餐。</p>

<h3>否决项和优化项的区别</h3>
<p>否决项是「不满足就一定出问题」，比如出口地区不在服务范围、出口 IP 被大量共享、链路丢包严重。优化项是「满足会更顺」，比如独享、更低延迟、更长的租期。预算有限时，先保证否决项，再考虑优化项。</p>

<h3>打勾之前先固定测试环境</h3>
<p>用同一台设备、同一个浏览器配置文件做测试，不要一边换设备一边换线路。变量太多时，你无法判断是哪一项起了作用。建议新建一个干净的浏览器配置文件，测试期只在这个配置文件里操作。</p>

<h2>二、三项否决条件</h2>
<p>这三条任何一条不通过，后面的钱都建议先别花。</p>

<h3>地区必须在服务覆盖范围内</h3>
<p>查询方式是 <code>curl -s https://ipinfo.io/json</code> 看 country 与 region。IP 归属地显示美国但注册地在别处的情况不少见，可以再用 whois 查 <code>whois 1.2.3.4</code> 的 netname 与 country 字段交叉确认。两地不一致时，以注册信息为准判断风险，不要只看界面上的国旗。</p>

<h3>出口不能被大量账号共用</h3>
<p>共享出口的直接后果是别人出问题你跟着受牵连。判断方法有限但有效：查 IP 的反向解析、看 ASN 下是否挂了异常的域名集合、用公开的黑名单查询页看是否被列入。独享住宅 IP 的月租通常在几十到一两百元区间，共享池按流量计费常见每 GB 几元到十几元，两者价格差在合理范围内，仅供参考。</p>

<h3>链路延迟和丢包要在可用区间</h3>
<p><code>ping -n 50 claude.ai</code> 看平均延迟与丢包。跨太平洋线路 150 到 220 毫秒属正常，超过 300 毫秒或丢包超过 3% 就该换线路。延迟高的典型表现不是打不开，而是长回复到一半停住、附件上传卡在 90%。</p>

<h2>三、四项加分条件</h2>
<p>否决项过了之后，按下面顺序投入预算，性价比从高到低。</p>

<h3>加一：租期长于使用周期</h3>
<p>住宅 IP 租期到期被回收是最常见的「莫名换 IP」原因。按月租用比按天拼接更稳，长期套餐折算下来月均通常比短租低两到四成，具体以服务商报价为准。使用周期超过三个月的，直接选季度或半年套餐。</p>

<h3>加二：同城不跨州</h3>
<p>同一城市内的 IP 变动影响很小，跨州就会带来时区、DNS 解析节点、内容分发节点的一连串变化。选线路时优先挑城市固定的套餐，而不是「美国随机」。</p>

<h3>加三：独立配置文件</h3>
<p>成本几乎为零但收益明显。一个账号配一个浏览器配置文件、一条出口，出问题时能干净地复现。Chrome 的个人资料路径在 <code>chrome://version</code> 里可以看到，复制一份改个名字就是新的隔离环境。</p>

<h3>加四：可控的重播策略</h3>
<p>部分服务商支持在控制面板里手动重播并保留原网段。这类功能在排查时很有用：能主动换 IP，也能在换到不理想的城市时快速回到原来那条。</p>

<h2>四、按时间顺序执行</h2>
<p>清单不是一次性动作，分三个阶段各查一遍最省事。</p>

<h3>开号前、开号后、付费后</h3>
<p>开号前只查否决项，确认线路可用；开号后四十八小时内不要换线路、不要改时区，让登录记录形成稳定序列；付费后一周内保持同样的环境，因为这段时间是订阅状态与账号环境互相确认的窗口。三次检查各花不到五分钟，能省掉大部分返工。</p>

<h2>常见问答</h2>
<h3>住宅 IP 的时区必须和出口城市一致吗？</h3>
<p>答：建议一致。时区是浏览器暴露给页面的少数本地信息之一，也是最容易被比对的一项。出口在洛杉矶而系统时区是东八区，虽然不一定立刻出问题，但会让环境描述出现明显矛盾。改时区只需两步，成本极低，没理由留着这个矛盾。</p>

<h3>延迟 250 毫秒算不算高？</h3>
<p>答：在跨太平洋住宅线路上属于可接受区间。体感上首字返回会慢半拍，但不影响正常对话。真正需要关注的是抖动和丢包：平均 250 毫秒但波动在 20 毫秒以内，比平均 180 毫秒却频繁跳到 600 毫秒要好用得多。</p>

<h3>同一账号在两台设备上登录，出口必须一样吗？</h3>
<p>答：尽量一样。两台设备走不同城市的出口，登录历史里会同时出现两个地点，属于典型的异常模式。如果确实需要移动使用，让手机和电脑走同一条线路的同一城市出口，至少保证城市级一致。</p>

<h3>清单都过了还是被要求验证，是不是白做了？</h3>
<p>答：不是。要求验证有很多触发条件，包括浏览器更新、Cookie 清空、异地网络切换。清单的作用是把可控变量降到最低，让你能快速判断问题出在哪一层，而不是保证一次都不触发验证。</p>
